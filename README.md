# 성심당 사랑기사 평가 시스템

한가족신문 PDF를 올리면 AI가 사랑기사를 자동으로 찾아 실천자별로 점수를 매기고,
웹 화면에서 검수·확정·집계까지 처리하는 시스템입니다.

- **프론트엔드** (저장소 루트, React + Vite) — 대시보드 · 기사 검수 · 호수 관리 · 실천자 점수 · AI 챗봇
- **백엔드** ([backend/](backend/), FastAPI + PostgreSQL) — PDF 기사 추출(GPT Vision) · AI 채점 · 검수 기록 저장
- **데이터베이스** (Neon PostgreSQL, 클라우드) — 여러 컴퓨터에서 같은 데이터를 공유

```
신문 PDF 업로드 → AI 기사 추출 → AI 채점 → 사람 검수·확정 → 실천자별 점수 집계·엑셀
```

---

## 🙋 담당자 사용법 (일상 운영)

### 1. 시작하기

`backend/사랑기사_시스템_시작.bat` 를 **더블클릭**하면 끝입니다.
서버가 켜지고 브라우저에 화면(http://127.0.0.1:8000)이 자동으로 열립니다.

- 최소화된 검은 창(*SSD server*)이 하나 생기는데, **프로그램 본체이니 닫지 마세요.** 닫으면 시스템이 꺼집니다.
- 이미 켜져 있는 상태에서 다시 더블클릭하면 화면만 새로 열립니다.
- 컴퓨터를 켤 때마다 자동으로 시작하려면 `backend/시작프로그램_등록.bat` 을 한 번 실행해 두세요.

### 2. 신문 업로드 · AI 채점 (업로드 탭)

1. 파일명에 호수가 들어간 PDF를 준비합니다 (예: `한가족신문_956호.pdf` — 호수는 파일명에서 자동 인식).
2. 발행월을 지정하고 파일을 드래그해서 올립니다.
3. 기사 추출 → AI 채점이 자동으로 진행됩니다 (자동 채점 켬 기준). 진행 상황이 화면에 표시됩니다.
4. 같은 파일을 다시 올리면 중복 업로드로 막고 기존 문서를 대신 열어줍니다.

### 3. 기사 검수 (검수 탭) — 가장 중요한 일

AI가 스스로 확정하지 못한 기사가 **재확인 필요** 탭에 모입니다.

- 기사를 열어 본문을 읽고 **0 · 1 · 2 · 4 · 5점** 중 하나로 확정합니다 (키보드 숫자키로도 가능).
- 실천자가 여러 명인 기사는 실천자마다 행이 나뉘어(예: `1810-1`, `1810-2`) **각각** 점수를 줍니다.
- **승인** 탭의 "AI 점수대로 일괄 확정" 버튼으로 자동 채점 건을 한 번에 확정할 수 있습니다.
- 내용이 같은 기사는 "중복 제외"로 처리하면 1건만 점수에 반영됩니다.
- 화면 맨 아래 **"점수 유형 안내"** 를 누르면 1번/4번 유형 등이 무슨 뜻인지 확인할 수 있습니다.
- 확정 내역은 검수자 이름과 함께 DB에 기록되어 "검수 이력"에서 볼 수 있습니다.

### 4. 나머지 화면

| 탭 | 하는 일 |
|---|---|
| **대시보드** | 호수별 현황 요약. 카드를 누르면 해당 검수 화면으로 이동, 표 제목을 누르면 정렬 |
| **호수 관리** | 호수별 검수 진행률 현황판. 연필로 발행월·이름 수정, "검수/채점" 버튼으로 남은 작업 바로가기 |
| **실천자 점수** | 실천자별 누적 점수 확인 + 엑셀 다운로드 (선택 호수 / 전체 기간). 예전 '사원 관리' 탭이며, 인사 명부 DB가 없어 사원 명단 기능은 제거했습니다 |
| **AI 챗봇** (우하단 말풍선) | "1810 알려줘", "1810건들 알려줘", "미처리 기사 보여줘" 처럼 질문하면 기사·현황을 찾아줍니다 |

### 5. 여러 컴퓨터에서 같이 쓰기

데이터는 전부 클라우드 DB에 저장되므로, 각 컴퓨터에 이 프로그램을 설치하고
`backend/.env` 의 `DATABASE_URL` 을 똑같이 넣으면 **업로드·검수 내용이 실시간으로 공유**됩니다.

## 📏 점수 기준 요약

**AI가 자동 확정하는 유형**

| 유형 | 점수 | 예시 |
|---|---|---|
| 4번 유형 | 2점 | 손수 만든 음식·선물, 본인 소유 물품·직접 재배 농산물 나눔, 자택 초대(사내부부 공동 초대는 각 1점), 고객 칭찬 사연 |
| 5번 유형 | 1점 | 사비로 산 5천 원 이상 선물, 카풀, 물품 빌려줌, 사비 식사 대접 |
| 점수제외 | 0점 | 사적 관계의 일상 예의, 회사 물품·탕비실 음료 전달, 개인 결제자 없는 모임, 4개월 이상 지난 일 |

**사람이 확인 후 확정하는 유형** — 화면에 "재확인"으로 표시

| 유형 | 확정 시 | 예시 |
|---|---|---|
| 1번 유형 | 5점 후보 | 1년 이상 근속 멘티가 추천한 멘토 활동, 갈등 중재·관계 회복 |
| 2번 유형 | 4점 후보 | 평가단 만장일치 감동 사례, 위기·희생 속 실천 |
| 기타내용 | 검토 필요 | 사크리케어 3개월+ 봉사, 전년도 기부, 본인 헌혈 |

최종 확정 점수는 **0 · 1 · 2 · 4 · 5점**만 사용하며, 같은 내용의 기사는 작성자가 달라도 1건만 반영합니다.
세부 기준은 [backend/prompts/score_prompt.py](backend/prompts/score_prompt.py)에 있습니다.

## 💻 새 컴퓨터에 설치하기

### 방법 A — 담당자용 (개발 지식 불필요) ★ 추천

기존에 쓰던 컴퓨터가 있다면 프로그램 폴더를 통째로 옮기면 됩니다.

1. 기존 컴퓨터에서 **프로그램 폴더 전체**를 USB나 공유폴더로 복사합니다.
   (화면 파일 `dist` 폴더와 `backend\.env` 설정 파일이 함께 복사되는지만 확인하세요.
   `backend\.venv` 폴더는 커서 빼고 복사해도 됩니다 — 설치 시 다시 만들어집니다.)
2. 새 컴퓨터에 붙여넣은 뒤 `backend\새컴퓨터_설치.bat` 을 **더블클릭**합니다.
   - Python 확인·설치 → 구성요소 설치 → 설정 확인까지 알아서 진행됩니다 (처음 한 번, 몇 분 소요).
3. 설치가 끝나면 자동으로 시스템이 시작됩니다. 이후에는 `사랑기사_시스템_시작.bat` 만 쓰면 됩니다.

`.env` 파일이 없다는 안내가 나오면, 기존 컴퓨터의 `backend\.env` 를 복사해 넣고 다시 실행하세요.
(데이터는 클라우드 DB에 있으므로 `.env` 만 같으면 기존 내용이 그대로 보입니다.)

### 방법 B — 개발자용 (저장소에서 새로 구성)

필요한 것: [Python 3.12+](https://www.python.org/downloads/), [Node.js 18+](https://nodejs.org/), Git

```bash
git clone https://github.com/jungsuryeon/BREDRED_simplified.git
cd BREDRED_simplified

# 1) 프론트 빌드
npm install
npm run build

# 2) 백엔드 준비
cd backend
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

3) `backend/.env.example` 을 복사해 `backend/.env` 를 만들고 두 가지를 채웁니다:

```
OPENAI_API_KEY=발급받은 OpenAI 키
DATABASE_URL=팀에서 공유하는 PostgreSQL 주소
```

(화면 폴더는 저장소의 `dist` 를 자동으로 찾습니다. 다른 위치에 두려면 `FRONTEND_DIST` 로 지정)

4) `backend/사랑기사_시스템_시작.bat` 더블클릭 → http://127.0.0.1:8000 이 열리면 완료.

> ⚠️ `.env` 에는 비밀 키가 들어가므로 절대 깃허브에 올리지 마세요 (`.gitignore` 로 이미 제외되어 있습니다).

## 🛠 개발자 안내

```bash
npm run dev        # 프론트 개발 서버 (http://localhost:5173, /api/v1 요청은 127.0.0.1:8000 백엔드로 프록시)
npm test           # 프론트 테스트
npm run typecheck  # 프론트 타입 · 미사용 코드 점검
cd backend && python -m pytest tests/   # 백엔드 테스트
cd backend && .venv\Scripts
uff check . && .venv\Scripts
uff format --check .   # 백엔드 스타일 · 미사용 코드 점검 (ruff.toml)
```

코드를 고친 뒤에는 위 점검 4가지를 모두 통과시키는 것을 기준으로 합니다.

- 기본 데이터 출처는 DB입니다. 백엔드 없이 옛 데모(Mock) 데이터로 화면만 보려면 `.env` 에 `VITE_ARTICLES_SOURCE=mock` 을 넣으세요 (전체 옵션은 [.env.example](.env.example) 참고).
- 챗봇을 LLM 모드로 쓰려면 `VITE_CHAT_PROVIDER=llm` 과 `OPENAI_API_KEY` 를 설정합니다 (기본은 규칙 기반으로 키 없이 동작).
- **작업 규칙: main 에 직접 푸시하지 않습니다.** 브랜치를 만들어 PR로 올리고 팀 확인 후 병합합니다 ([docs/git-guide.md](docs/git-guide.md)).
- 프론트 코드 구조·파일별 설명은 [docs/dev-guide.md](docs/dev-guide.md) (이전 README), 연동 구조는 [docs/scoring-integration.md](docs/scoring-integration.md), API 명세는 [docs/api-spec.md](docs/api-spec.md) 참고.
- 보안 옵션
  - **로그인(접속 코드)**: `backend/.env` 에 `API_ACCESS_TOKEN` 을 설정하면 화면이 **로그인 화면(이름 + 접속 코드)**부터 열립니다. 이름은 검수 이력에 기록되고, 코드는 그 브라우저에만 저장됩니다(사이드바 하단 로그아웃으로 삭제). 코드를 5분 안에 10번 틀리면 잠시 차단됩니다. 비워 두면 예전처럼 로그인 없이 열립니다. Render 배포(`render.yaml`)는 코드를 자동 생성하며, 값은 Render 대시보드 Environment 에서 확인합니다.
  - 프론트 `.env` 의 `VITE_API_ACCESS_TOKEN` 도 되지만, `VITE_` 값은 화면 코드에 그대로 들어가 **누구나 볼 수 있으므로** 쓰지 않는 것이 좋습니다.
  - 화면의 **백엔드 설정**(OpenAI 키 · DB 주소 변경)은 기본적으로 **서버를 실행 중인 PC 자신**에서만 열립니다. 클라우드 등 원격 서버에서 쓰려면 서버에 `SETTINGS_ADMIN_TOKEN` 을 설정하고, 브라우저 localStorage `bredred-admin-token` 에 같은 값을 넣으세요.
  - **사람 손을 덜 타게 하는 옵션**(`backend/.env`, 둘 다 기본은 꺼짐):
    - `AUTO_CONFIRM_AFTER_SCORING=1` — 채점이 끝나면 AI가 확실하게 확정하는 건(4번·5번·점수제외, 추출 경고 없음)을 `AI 자동 확정` 이름으로 바로 확정합니다. 1번·2번·기타 유형은 그대로 사람이 검수합니다. 검수 이력에 자동 확정으로 남습니다.
    - `SCORING_USE_FEEDBACK=1` — 검수자가 AI 점수를 고친 최근 사례(이름·부서 제외)를 다음 채점 요청에 참고로 함께 보냅니다. 모델을 다시 학습하지 않는 방식이라 언제든 끌 수 있고, 채점 규칙이 항상 우선합니다.

## 📂 폴더 구조

```
├─ src/               # 프론트엔드 (React + Vite + Tailwind)
│  ├─ app/pages/      # 대시보드·검수(review/)·업로드·호수·실천자 점수 화면
│  ├─ app/components/ # 공용 컴포넌트 (점수 유형 안내, 챗봇, 로그인, scoring/ 등)
│  └─ app/api/        # 백엔드 호출 레이어 (config · auth · http · scoringDb · scoring)
├─ backend/           # 채점 백엔드 (FastAPI + PostgreSQL)
│  ├─ api/            # 웹 API — HTTP 요청·응답만 담당 (업로드·채점·검수·호수·통계)
│  ├─ services/       # 업무 로직: 추출·채점, review_view(화면용 순수 변환), review_service(조회·일괄 확정)
│  ├─ db/             # PostgreSQL 접근 (documents · articles · evaluations · reviews)
│  ├─ prompts/        # AI 채점 기준 프롬프트
│  ├─ 새컴퓨터_설치.bat          # ★ 새 컴퓨터 최초 1회 설치
│  └─ 사랑기사_시스템_시작.bat   # ★ 담당자용 원클릭 실행
└─ docs/              # 개발 문서 (상세 코드 구조는 docs/dev-guide.md)
```
