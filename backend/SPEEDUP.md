# 처리 속도 개선 (30분+ → 5분 이내 목표)

## 원래 느렸던 이유

1. **페이지 추출이 완전 순차 처리** (`services/extraction_job.py`)
   - 페이지 1장을 렌더링 → GPT-4o Vision 호출 → DB 저장이 끝나야 다음 페이지 시작.
   - Vision 호출 1건이 30~60초 걸리므로 페이지 10~15장이면 이 단계만 10~15분.

2. **기사 채점도 완전 순차 처리** (`services/scoring_job.py`)
   - 기사 1건씩 GPT 호출 → 저장 반복. 기사 40~60건이면 10~20분 추가.

3. **페이지 이미지를 PNG로 전송**
   - 잡지 지면(사진 많음)의 200DPI PNG는 수 MB. base64 인코딩 후 매 요청마다
     업로드하므로 요청당 수 초씩 낭비.

4. **요청 타임아웃 없음 + 매 호출마다 OpenAI 클라이언트 새로 생성**
   - 응답이 멈춘 요청 1건이 전체 작업을 무기한 붙잡을 수 있었음.

## 변경 내용

| 파일 | 변경 |
|---|---|
| `services/extraction_job.py` | 페이지별 Vision 호출을 `ThreadPoolExecutor`로 동시 실행 (기본 5개). DB 저장은 메인 스레드에서 완료 순서대로 처리. 치명적 오류(키 누락·인증 실패 등) 발생 시 대기 중인 페이지 즉시 취소. |
| `services/scoring_job.py` | 기사별 채점 호출을 동시 실행 (기본 6개). |
| `utils/pdf_pages.py` | `render_page_jpeg()` 추가 — PNG 대비 수 배 작은 JPEG(품질 80)로 전송. |
| `services/openai_client.py` | 클라이언트 1회 생성 후 재사용, 요청 타임아웃 120초 추가(멈춘 요청은 끊고 재시도). |
| `.env.example` | 아래 신규 설정 항목 문서화. |

## 새 환경 변수 (.env)

```
OPENAI_TIMEOUT_SECONDS=120   # OpenAI 요청 1건 최대 대기 시간(초)
EXTRACTION_CONCURRENCY=5     # 동시에 추출할 페이지 수
SCORING_CONCURRENCY=6        # 동시에 채점할 기사 수
```

- `RateLimitError`가 자주 보이면 숫자를 낮추세요 (예: 3).
- OpenAI 요금제 Tier가 높다면 8~10까지 올려도 됩니다.

## 예상 효과

- 추출: 15페이지 × 45초 ≈ 11분 → 동시 5개 ≈ **2~3분**
- 채점: 50기사 × 15초 ≈ 12분 → 동시 6개 ≈ **2~3분**
- 합계: **30분+ → 약 4~6분** (여기에 JPEG 전송으로 요청당 업로드 시간 추가 단축)

동작 방식(추출 → 검토 → 채점 흐름, API, DB 스키마)은 그대로이며 결과 형식도 변하지 않습니다.

## 추가 안정화 (실측 중 발견되어 수정)

- **429(분당 토큰 한도) 재시도 대기 강화**: OpenAI가 알려주는 짧은 대기 시간만 기다리면
  여러 워커가 경쟁할 때 재시도가 계속 실패한다. 지수적으로 늘어나는 최소 대기(3→6→12→24→48초)
  + 무작위 지터를 적용하고 재시도를 5회로 늘렸다. → Tier 1 키에서도 중단 없이 완주 확인.
- **깨진 JSON / 검증 실패 자동 재호출**: gpt-4o-mini가 가끔 잘못된 JSON을 출력하거나
  rule_id를 빠뜨린다. 채점 실패율 38% → 7% → (재시도 후) 대부분 자동 복구.

## 실제 PDF 실측 (UNA FAMIGLIA 2026년 제956호, 294쪽)

로컬 구간 실측값:

- 사랑기사 페이지 검출: **3.1초**, 검출 결과 **197페이지** (89~285쪽, 전부 실제 사랑의 챔피언 지면임을 확인)
- 페이지 렌더링: JPEG 0.6초/장 (병렬 워커 안에서 API 대기와 겹쳐 실행되므로 전체 시간에 거의 안 더해짐)
- 요청당 이미지 크기: PNG 평균 1.33MB → JPEG 평균 0.34MB (**약 1/4로 감소**)

API 구간 실측값 (Tier 1 키, 동시 6/8):

- Vision 추출: 페이지당 4.7초 (30페이지 141초 완주, 실패 0) — 기사 2.0건/페이지
- 채점: 기사당 7.7초 (60건 462초, gpt-4o-mini 호출 1건 자체는 30~60초이나 병렬로 상쇄)

이를 기반으로 한 이 문서(197페이지, 기사 약 390건) 전체 예상:

| 설정 | 추출 | 채점 | 합계 |
|---|---|---|---|
| 기존 코드 (순차) | 1.4시간+ | 3시간+ | **4시간 이상** |
| 개선 후 · Tier 1 (동시 6/8) | 10~15분 | 40~50분 | 약 1시간 |
| 개선 후 · Tier 2 (동시 20/25) | 4~5분 | 6~8분 | **10~13분** |

병목은 더 이상 코드가 아니라 **OpenAI 요금제 등급(Tier)** 입니다.
Tier 1은 gpt-4o가 분당 30,000토큰으로 제한되어 코드가 아무리 빨라도
분당 약 24페이지 이상 처리할 수 없습니다. 누적 결제 $50 이상이면 자동으로
Tier 2(분당 450,000토큰)가 되어 위 표의 아래 행이 적용됩니다.

참고: 이 956호는 사랑기사가 197페이지인 특대호입니다. 사랑기사가 10~30페이지인
일반적인 호라면 Tier 1에서도 5~10분 내에 완료됩니다.
